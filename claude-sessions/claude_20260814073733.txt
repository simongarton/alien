A solid pattern: use an **S3 backend for state** with **native S3 locking** (Terraform 1.10+, no DynamoDB table needed anymore) or DynamoDB if you're on an older version, then organize as a root module per environment (`envs/dev`, `envs/prod`) that calls a shared `modules/api-lambda` module defining the Lambda + API Gateway + IAM role. The main tradeoff is state granularity: one state file per environment is simple but means a bad `apply` risks the whole stack, whereas splitting state per-component (e.g., separate state for the Lambda vs. the gateway) is safer but adds cross-state data-source wiring complexity — for a single API+Lambda pair, one state per environment is usually the right call.
